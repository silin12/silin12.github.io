2026.11.20 前端 v1.0.10

最新

UI 镜像 :v1.0.10（digest sha256:1950914e…d1cfb3，:latest 同内容）· 脚本 main（TP_UI_IMAGE_TAG=v1.0.10）· panel / core 仍 v1.0.4

  • feat系统设置新增 「定时备份」页，参考 OpenWrt 的备份/恢复布局：左侧「备份策略 / 反向拉取 / 本机备份文件」，右侧「恢复」，窄屏自动上下堆叠。
  • feat备份对象只有数据库：每次对 trojan_panel_db 做 mysqldump 打包成 tp-backup-<时间>.tar.gz，不含证书与 config.json（换 VPS 会重签证书，恢复旧证书没有意义）。
  • feat保留策略：可设启用开关、每日执行时间、保留份数（1–30，默认 2），支持「立即备份」「下载」「删除」，列表显示大小与时间。
  • feat恢复提供两种方式：整库覆盖恢复（整库回滚），以及「仅补缺失账号」——备份先导入临时库 tp_restore_merge，按「用户名 + 邮箱」判重，只 INSERT 缺的账号，不删不改、不动其它表、不重启容器。
  • fix恢复前自动生成回滚点 /tpdata/backup/pre-restore-<时间>.sql.gz（保留最近 2 个），覆盖恢复失手也能退回恢复前状态。
  • feat反向拉取：/backup-pull/latest?token=… 供 NAS 侧定时取最新包，页面上有开关；关闭时返回 403「拉取令牌已关闭」，令牌可重置。
  • fix上传恢复加校验：上限 200 MB，从归档里抽 dump.sql.gz 并做 gzip 校验 + 断言含 CREATE TABLE 才导入；nginx 侧 client_max_body_size 200m、proxy_request_buffering off、超时 1800s。
  • build前端镜像推 :v1.0.10，:latest 同步指向同一内容；源码侧新增 backup.vue、系统设置页加 tab、中英文语言包补 63 条 config.backup*、请求超时 5s → 15s。
  • build一键脚本改造：新增 TP_UI_IMAGE_TAG（默认 v1.0.10），拉不到就用本机同 tag 再退 TP_IMAGE_TAG；两套 nginx 模板补 /backup/ 与 /backup-pull/；新增 install_tp_backup（装 tpbackup-api.py + systemd tpbackup-api）并挂到菜单 28；前端升级路径改成先拉镜像再删容器，避免回退时本地镜像已被删掉。
  • note推荐用法：日常换机/迁移走「整库覆盖恢复」；只是担心新加的账号丢失，用「仅补缺失账号」即可，已有账号的流量、到期时间不会被覆盖。
  • note本轮 panel / core 不动：core 的 v1.0.4 与 v1.0.3 是同一 digest（纯重打标签），前端单独打 v1.0.10。

安装与升级

一键安装（按版本固定）

# 装最新：后端/内核 v1.0.4 + 前端 v1.0.10（含定时备份与恢复页）
TP_IMAGE_REPO=ghcr.io/silin12 TP_IMAGE_TAG=v1.0.4 TP_UI_IMAGE_TAG=v1.0.10 bash <(curl -fsSL https://raw.githubusercontent.com/silin12/install-script/main/install_script.sh)

# 只把前端退回 v1.0.4（没有定时备份页）
TP_IMAGE_REPO=ghcr.io/silin12 TP_IMAGE_TAG=v1.0.4 TP_UI_IMAGE_TAG=v1.0.4 bash <(curl -fsSL https://raw.githubusercontent.com/silin12/install-script/main/install_script.sh)

# 退到 v1.0.2 基线 / v1.0.1 / v1.0.0（前端同样要指 v1.0.4 以下）
TP_IMAGE_REPO=ghcr.io/silin12 TP_IMAGE_TAG=v1.0.2 TP_UI_IMAGE_TAG=v1.0.4 bash <(curl -fsSL https://raw.githubusercontent.com/silin12/install-script/main/install_script.sh)

TP_IMAGE_REPO=ghcr.io/silin12 TP_IMAGE_TAG=v1.0.1 bash <(curl -fsSL https://raw.githubusercontent.com/silin12/install-script/main/install_script.sh)

TP_IMAGE_REPO=ghcr.io/silin12 TP_IMAGE_TAG=v1.0.0 bash <(curl -fsSL https://raw.githubusercontent.com/silin12/install-script/main/install_script.sh)

TP_IMAGE_TAG 默认 v1.0.4（panel / core），TP_UI_IMAGE_TAG 默认 v1.0.10（前端），两个变量可分别指定。前端拉不到 GHCR 上的 tag 时，脚本会先用本机同 tag 的镜像，再退到 TP_IMAGE_TAG，不会把界面直接退回旧版。卸载或换版本时请带上与安装时相同的 tag，否则单镜像清理会提示找不到镜像。

升级：菜单 8 / 9 / 10（不重装）

# 目标版本写在 TP_IMAGE_TAG / TP_UI_IMAGE_TAG，进菜单后点 8 / 9 / 10
TP_IMAGE_REPO=ghcr.io/silin12 TP_IMAGE_TAG=v1.0.4 TP_UI_IMAGE_TAG=v1.0.10 bash <(curl -fsSL https://raw.githubusercontent.com/silin12/install-script/main/install_script.sh)

8 = Update Trojan Panel Frontend（比对 TP_UI_IMAGE_TAG），9 = Update Trojan Panel Backend，10 = Update Trojan Panel Core。脚本先 docker inspect -f '{{.Config.Image}}' 取容器当前镜像，与 ${TP_IMAGE_REPO}/<仓库>:${TP_IMAGE_TAG} 比对，不一致才动；一致就打印「已是最新」。真正执行时会从 config.ini 读回 MariaDB / Redis / grpc / server 端口，flushall 清 Redis，docker rm 旧容器，拉新 tag，按原参数重建——数据库、节点配置、证书都不动。

换过 core 之后，已存在节点的 config-*.json 不会被重写，REALITY 节点要在面板里逐个保存一次才会带上 minClientVer。

只换某个容器（不重装）

docker pull ghcr.io/silin12/trojan-panel-ui:v1.0.2
docker rename trojan-panel-ui trojan-panel-ui-old
docker run -d --name trojan-panel-ui --restart always --network=host \
  $(docker inspect -f '{{range .Config.Env}}-e {{.}} {{end}}' trojan-panel-ui-old) \
  $(docker inspect -f '{{range .Mounts}}-v {{.Source}}:{{.Destination}} {{end}}' trojan-panel-ui-old) \
  ghcr.io/silin12/trojan-panel-ui:v1.0.2
docker rm -f trojan-panel-ui-old
